# AstoryClient/Tools/LogSeal — расшифровка журналов игроков (.alog / .acrash)

Релизный клиент пишет журналы только зашифрованными (AsdaLogSeal, с 16.10.2026). С 19.10.2026 лаунчер при запуске сам
выгружает журналы прошлых игровых сессий на dev-сервер (приёмник LogDrop), а этот инструмент забирает их и расшифровывает
на машине владельца. Протокол: `Reports/release_logs_2026-10-19/00_SPEC.md`.

## Файлы

| Файл | Что |
|---|---|
| `Decrypt.bat` | перетащить на него файл(ы) `.alog`/`.acrash` или папку → рядом `<имя>.txt` (у падений ещё `<имя>.d\` с minidump) |
| `FetchAndDecrypt.bat` | забрать новое с сервера и расшифровать в `@@ASTORY_DEV_ROOT@@\_player_logs\<логин>\<дата>\` (вне депо Perforce) |
| `fetch_and_decrypt.py` | то же из консоли: `--src <локальная папка LogDrop>`, `--dest <папка>`, `--all` (заново всё), `--kinds alog,acrash`, `--limit N` |
| `logseal.py` | тонкая обёртка: любые команды `asda_logseal.py` (`decrypt`, `check`, `selftest`, `import-backup` …) |

Логика одна — `AstoryClient\Tools\asda_logseal.py` (его импортируют сборка релиза: `gen_build_crypto.py`,
`asda_update_format.py`). Здесь только загрузка этого модуля по пути — копий кода нет.

## Откуда берутся файлы

- Хранилище приёмника на сервере: `@@ASTORY_SERVER_ROOT@@\Working_ASDA\v2\LogDrop\<логин>\<ГГГГ-ММ-ДД>\<имя>.alog|.acrash` + `.json`
  (время, IP, id установки, вид, размер, keyId, SHA-256). Без логина/с неизвестным логином — папка `_unknown`.
- ★ 23.11.2026 (А7.2): забирается **по SSH**, шара `\\@@ASTORY_SERVER_HOSTNAME@@` больше не используется (она висит без таймаута; правило «сервер — только
  SSH»). Список — PowerShell по SSH, файлы — `scp` пачками с их `.json` (ключ `%USERPROFILE%\.ssh\@@ASTORY_SSH_KEY_NAME@@`,
  `Administrator@@@ASTORY_SERVER_VPN_IP@@`, VPN Tailscale). Целость копии — SHA-256 файла = `sha256` из `.json` приёмника; не сошлось — копия
  стирается и не считается забранной. Локальная копия папки LogDrop — `--src` или переменная `ASDA_LOGDROP`.
- Тот же код забирает пакеты падений для раздела «Сбои клиента» админ-центра (`asda_admin.py crashes sync`, только `.acrash`):
  расшифровка — здесь, на ПК; в панель уходит только сводка (код, место, версия по времени, логин).
- Забранное помечается в `@@ASTORY_DEV_ROOT@@\_player_logs\.fetched.txt`; на сервере ничего не удаляется. Папка — вне `port\`
  (депо): данные игроков (IP, чат) и присланное извне не должны попасть в сабмит.
- Имена файлов внутри пакетов падения чистятся (без `:`, `..`, имён устройств; только внутри `<имя>.d\`, без перезаписи) —
  присланный нарочно испорченный пакет не может записать файл вне папки расшифровки.
- Вручную присланный файл игрока — просто `Decrypt.bat`.

## Ключ

Закрытый ключ — только в хранилище DPAPI владельца (`%APPDATA%\AsdaReborn\LogSealKeys`). Никуда не копировать.
Другой ПК / переустановка Windows: `python logseal.py import-backup <файл копии>` (пароль владельца).
Проверка: `python logseal.py check`. Подробности — шапка `asda_logseal.py`.

## Части одной сессии (★ 31.10.2026)

Клиент режет журнал сессии на части ≤ 4 МиБ (предел приёмника): `<ГГГГММДД-ЧЧММСС>_<pid>.alog`, затем `…_part2.alog`, `…_part3.alog`…;
хранит первую и последние части (всего 6), строки сжаты (запись TextZ). Каждая часть расшифровывается сама по себе. На сервере имя
файла случайное — сессию и номер части называют сведения внутри (`session_id=`, `part=`). Склейка в один текст:
`python logseal.py join <папки/файлы> -o <куда>` → `<сессия>.joined.txt` (части по порядку, пропуски названы: средние части клиент
удаляет сверх 6, хвостовые могут быть ещё не выгружены). `FetchAndDecrypt` склеивает сам: `_player_logs\<логин>\sessions\`.
В пакете падения `.acrash` с 31.10 — ещё `session_tail.txt`: последние ~64 тыс. символов журнала до падения.

## Как читать итог

`сегментов N, ошибок 0, обрезанных 0` — всё цело. «тег GCM не сошёлся» — подмена/порча. «хвост обрезан» — процесс упал во
время записи (всё до обрыва читается). Лаунчер перед отправкой сам отбрасывает недописанный последний кадр — его всё равно
нельзя расшифровать.

## ⚠ Логин не доказан

Логин (папка) заявлен клиентом игрока: лаунчер берёт его из `Sessions\<сессия>.alog.meta`, сервер проверяет только формат и
существование учётки. Подделать «чужой» логин можно; журнал можно и подделать целиком (ключ шифрования открытый).
Это диагностика, не доказательство против игрока.

## Где ищется закрытый ключ (19.10.2026)
1. `%APPDATA%\AsdaReborn\LogSealKeys` — основное хранилище (DPAPI учётки владельца).
2. Если там нет — подменный AppData упакованных приложений (`%LOCALAPPDATA%\Packages\*\LocalCache\Roaming\AsdaReborn\LogSealKeys`,
   `<диск>:\WpSystem\…`; туда Windows уводит запись из процессов Claude Desktop) и копия владельца `@@ASTORY_DEV_ROOT@@\_keys\LogSeal`.
   Найденный файл проверяется (DPAPI) и переносится в п. 1 — об этом строка «[ключ] … перенесён».
Ошибка «нет закрытого ключа для keyId …» значит, что ключа нет ни в одном из этих мест для текущей учётки Windows.
